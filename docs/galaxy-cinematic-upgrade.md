## 一、GPT-6 Astra 渲染管线全景（实测数据）

### 1.1 基本盘

| 项 | 实测值 |
| --- | --- |
| 引擎 | three.js **r180**（shader 头 `THREE_REVISION 180`），与本项目 `three@0.180.0` 完全同版 |
| 后处理库 | pmndrs `postprocessing`（EffectMaterial 的 `e0/e1/e2` 前缀 + `BlendOpacity` 是其多效果合并特征） |
| 上下文 | WebGL2，单 canvas，DPR=1（内嵌浏览器实测） |
| 粒子数 | 稳态 ~**4,642 点/帧**（1000×3 系统 + 773×2 + 96 亮星），开场峰值 ~2.7 万点/帧 |
| 程序数 | 6 个：1 个巨型粒子 shader（顶点 24KB）+ bloom 链 4 个 + 合成 1 个（片元 25KB） |
| 每帧 pass | 13 次全屏三角形绘制 + 13 次 FBO 绑定，60fps |

**关键事实：粒子总数与本项目几乎一致（本项目 4600 尘埃 + 300 星 + 180 远景 ≈ 5,080）。差距完全不在数量。**

### 1.2 每帧管线

```
Scene（HDR 线性空间，加法混合，一次渲染，无分层）
 → Luminance 阈值提取（4tap 盒式下采样 + smoothstep 软 knee，半分辨率 632×360）
 → Kawase 下采样 ×5 → mip 金字塔 6 级（632×360 → 316×180 → 158×90 → 79×45 → 40×23 → 20×12）
 → tent 滤波逐级上采样（UpsamplingMaterial：9tap 权重，radius 混合 supportBuffer，CoD:AW 方案）
 → EffectMaterial 单 pass 三效果合并合成：
     e0: 加法叠层纹理 × 强度
     e1: 镜头光学 —— 核心光斑 + halo + 软环 + 横/竖 anamorphic 拉丝（锐+柔各一）
         + 3 个 ghost（0.82/1.38/1.82× 光轴）+ 5 个挂亮星的次级光源
         + 脏玻璃（贴图折射 UV warp + 显影遮罩）+ 胶片颗粒（hash 噪声）
     e2: ACES Filmic 色调映射 → sRGB OETF 输出
```

### 1.3 粒子着色器要点（prog0.vert，24KB）

- **路径烘焙**：旋臂位置烘进 `uPathTexture`/`uPathShapeTexture` 纹理，粒子按 `orbitProgress` 流动——**与本项目 `galaxyScene.ts` 的 track texture 同构技术**。差别在分布细节：
  - 密度调制：`targetProgress += uDensityFalloff · sin(phase·2π)/2π`（沿臂聚簇）
  - z 向编织：`sin(progress·π·1.35 + depthPhase) · depth · 包络`（臂在深度上起伏）
  - 尺寸包络：中段粗两端细 `pow(sin(progress·π), 0.68)`，端点 `smoothstep(0,0.055,…)` 渐隐
- **亮度幂律**：`starBrightness` 逐星属性（0~2.8+），统一驱动：尺寸（`0.35+scale·3.8` px）、衍射芒强度（`smoothstep(1.45,2.8,brightness)`）、白核推进、镜头光晕挂载资格。
- **亚像素解析覆盖**：`<2px` 的星用三次 B 样条覆盖度积分 `astraCubicCoverage`（面积×d²）替代硬圆盘 → 微星永不闪烁。
- **衍射芒焊在 sprite**：`exp(-|y|·28)·(1-smoothstep(0.18,1,|x|))` 十字，仅最亮的少数星有。
- **白核能量转移**：`whiteCore = smoothstep(0.9,2.8,vBrightness)`，亮度超过阈值颜色向白推（摄影过曝），配合 ACES 形成"亮处泛白滚降"。
- **指针动量 GPGPU**：`ASTRA_PARTICLE_SIMULATION` 变体把速度状态渲染进 `uParticleMotionTexture`（ping-pong），`astraCoast` 用质量相关阻力 `2.3/√mass` + `exp(-age)` 回归 + 限速 0.5——"个体动量，无位置弹簧"。
- **文字避让**：`uTextBounds` 只**稀释散落场的内缘**（`keepInCenter = step(0.72, clearanceSeed)`），从不 alpha 挖洞破坏主体。

### 1.4 "群星归位"开场解码（uIntroProgress 时间线，全在顶点着色器）

1. **双星群参照系**：星系星飞行时，背景星野（独立 model matrix）**全程静止**——"镜头没动，是宇宙在归位"。
2. **交错起飞**：`start = 0.14 + seed·0.18`，`duration = 0.58 + travelSeed·0.1`——每颗粒子有自己的出发时刻与行程。
3. **弧线飞行（灵魂）**：途中绕目标旋转 `angle = sin(pull·π)·(0.44 + seed·0.22)`（≈25°~38°，钟形）——直线 lerp 是 PPT，弧线是引力捕获。
4. **落座缓动**：五次 smootherstep 与 `sin(pull·π/2)` 各混 50%——末端轻微加速"吸附"。
5. **先可见再汇聚**：散落态先淡入（`smoothstep(0,0.2)`）+ `sqrt(progress)` 长大——先见散落宇宙，再见它被整理。
6. 后续还有两套编排可借鉴：**吸积波**（径向传播的形成波前 + 高斯亮度冲击波 `exp(-((local-accretionEnd)·11)²)`）与**生长线**（螺旋从中心画出，诞生时刻 ∝ 半径）。

## 三、落地方案（玫瑰的"绽放"版电影感）

### P0 renderer 级（半天，观感收益最大）

1. **ACES**：`renderer.toneMapping = ACESFilmicToneMapping`（夜）/ `NoToneMapping`（昼，保持）。
   现有星星片元已在输出 >1 发光（`(1.0+core*mix(0.4,3.2,vProminence))`），被 Neutral 压平，换 ACES 立刻出现白核滚降。
2. **亮度幂律**：新增 `aBright` 属性，`bright = 0.35 + pow(random(),3)·1.65`（尘埃）/ `0.4 + pow(random(),2.6)·2.6`（星）。
   尺寸、白核、芒、光晕挂载全部挂到它上面；废除 `i%20` 尺寸/颜色周期。
3. **按亮度取色**：亮星 → 白 `#e3f3ff` / 暖橙 `#ffb878`；暗星 → 蓝 `#9ad8ff` / `#b5d4ff`。品牌调色板不变，分配逻辑变。

### P1 Bloom 核心（核心工程项）

4. **mip 金字塔 Bloom 替代双 composer**：新模块 `bloomPyramid.ts`，单 Pass 内完成
   阈值提取（软 knee）→ 6 级下采样 → tent 上采样 → 与场景加法合成。
   删除 `bloomComposer`/`camera.layers` 切换/星星 `layers.enable(1)`——场景从每帧两遍变一遍，反而更快。
5. **lvy 花心之光**：
   - 花心（签名锚点 `(0,0,-1.42)`）放柔光核 billboard（`exp(-r²k)`，发光 ~1.6 → Bloom 主来源）；
   - 24 颗最亮的星分配到签名笔画轨道上聚簇——**签名本身成为全图最亮区域**，构图有了引力锚点。

### P2 开场编排：绽放（对应"群星归位"的玫瑰语义版）

6. 共享 `deformation` GLSL 增加 `uIntro` 时间线 + 全局 `gIntroT`：
   - 花蕾态：粒子收缩于花心小球（`vec3(0,0,-0.9) + seeded offset`）；
   - 中心向外错峰绽放：`delay = mix(0, 0.55, smoothstep(0.2,3.4,radial)) + seed·0.18`（签名先开，花瓣外圈后开）；
   - **旋出弧线**：`rotate(p - bud, sin(t·π)·(0.4+seed·0.3))`——绽放路径是弧线不是直线；
   - 缓动：五次 smootherstep ⊕ `sin(t·π/2)`；
   - 尺寸 `sqrt(t)` 长大、透明度 `smoothstep(0,0.18,t)`；
   - 时长 2.6s，`setPage` 重播（短版），`reducedMotion` 直接 t=1；
   - 花心光核与花心 flare 在 `smoothstep(0.55,0.9,intro)` 点亮——"绽放完成、花心点亮"的电影节拍。
   - 零 CPU 开销：CPU 只递一个标量，全部在顶点着色器。

### P3 氛围微调（可选）

7. 大气层片元加 ±1.2/255 动态胶片颗粒（零新增 pass）。
8. 合成 pass 加花心专属克制的 halo + 一条横向拉丝（无 ghost/脏玻璃）。
9. 首屏构图：`worldHeight/9.4` → `/10.1` 修顶部溢出。

### 验收标准

- [ ] 60fps（dev 面板 `data-fps`），移动端 30fps 线不破
- [ ] 亮星有白核 + 衍射芒，微星不闪烁
- [ ] 花心是全图最亮处，签名可读且发光
- [ ] 首屏可见完整绽放序列，玫瑰不溢出视口
- [ ] 昼间主题、阅读模式、reduced-motion、`setPage` 行为不回归
- [ ] `pnpm check` + `pnpm test` 全绿

## 五、每篇文章一颗星图（per-post constellation，2026-09 第二期）

**需求**：现在只有首页有完整特效；文章页/其他页面的玫瑰直接消散成静态点场，缺乏"每篇不一样"的记忆点。目标：阅读时每篇文章背景是一幅**由种子确定的星图**，同文稳定、异文不同，全站覆盖。

**技术路线**（对齐 OpenAI 已解码的 `uPathShape*` 形变架构）：

1. **种子**：路径 FNV 哈希（复用 `pageScene.ts` 的哈希思路）→ mulberry32 PRNG。同 slug 恒定，跨文发散。
2. **轮廓家族**（`ambientScene.ts` 生成 6 条轮廓，对应玫瑰的 4 外圈 + 2 内圈行）：
   - 玫瑰线 rhodonea（k=3..6，品牌呼应）、利萨茹 3D、轨道椭圆、波形带、螺散云。
   - 每行带半径/相位/z 偏移的种子扰动，形成成套多轮廓图。
3. **形变**：`galaxyScene.ts` 增加第二轨迹纹理 `uAmbientTracks` + `uAmbientBlend`（首页 0 ↔ 阅读 1，导航时指数交叉淡入）。顶点着色器分支门控（`blend>0` 才采样），粒子在玫瑰轨道与星图轮廓间 morph；星星作为"珠链"勾出星座轮廓。
4. **性格参数**：漂移方向/速度、闪烁偏置、花心光核存在感（`uAmbientGlow`）均按种子定。
5. **文本保护**：星图整体透明度 ×0.6 + 现有 readableArea/quiet 盒照常生效。

**性能预算**（硬约束）：
- 绘制调用不变（同一批粒子 morph，非新增系统）；无新增渲染 pass / RT。
- 顶点着色器多一次均匀分支 + ≤2 次纹理读取（仅阅读模式激活）。
- CPU 仅在 `setPage` 时烘焙 6×513 采样（微秒级）。
- 移动端减量逻辑（drawRange 2800 / 30fps 上限 / DPR 1.25）原样保留。
- 验收：桌面阅读页 fps ≥55，移动端不破 30fps 线。

**验收**：≥3 篇不同文章呈现肉眼可辨的不同星图；首页玫瑰不受影响；reduced-motion 静态但仍有星图；导航交叉淡入平滑无跳变。

### 第二期走查修复（同日）

| 问题 | 根因 | 修复 |
| --- | --- | --- |

### 拖尾三次调整（用户反馈"太快"）+ 玫瑰左右失衡修复（同日）

**拖尾减速率**：用户观感"推开的粒子回来得太急"。

| 参数 | 旧 | 新 |
| --- | --- | --- |
| 衰减率（wakeOffset `fade`） | `exp(-age·(1.4+0.8z)/mass)`（中质量 τ≈0.7s） | `exp(-age·(0.8+0.45z)/mass)`（τ≈1.2s，重粒 ≈2s） |
| `WAKE_LIFETIME` | 2.4s | **3.2s**（测试 pump 170→210 同步） |
| 动量 EMA 衰减 | `exp(-dt·2.6)`（τ≈0.38s） | `exp(-dt·2.0)`（τ≈0.5s，划过滑行更久） |

冻结实测：扫后 1.5s 残留清晰可见（旧参数同期仅 ~12% 已消失），整条路径扰动持续、粒子仍贴等高线不散架。

**玫瑰左右投影失衡**：用户截图显示左半圆环致密、右半稀疏扁平。轨迹数据本身是平衡的（3D 长度 52/48），**元凶是姿态**：

- 关键发现：`paint()` 每帧执行 `group.quaternion.copy(orientation)`，**真正生效的姿态是 `RotationMotion` 的 home `Euler(0.12,-0.12,-0.025)`**；此前 `group.rotation.set(0.42,-0.16,-0.26)` 的"倾角修复"改的是每帧被覆盖的死值，从未起效（两个姿态失衡度同为 ~0.41，投影质量 71/29）。
- 修复：轨迹点按姿态投影做左右质量网格搜索，选定 **`Euler(0.35,-0.55,-0.30)`**——投影质量 50/50、四象限 0.28/0.22/0.21/0.29，`group.rotation` 与 `RotationMotion` home 两处同步（拖拽回位姿态=初始姿态）。
- 像素实测：修改前亮粒子 L/R=71/29 → 修改后 **49/51**；深浅两主题玫瑰均为饱满圆形花冠，暖色星均匀分布；阅读页星座无回归。

**玫瑰上下失衡跟进**（用户反馈"下面大了"）：纯计数平衡≠视觉平衡——俯仰让近镜头弧线透视增粗。按左右+上下+范围三重目标（含 persp² 面积权重）重搜，终定 **`Euler(0.28,-0.50,-0.40)`**；渲染像素实测上下平均 reach 109.5 vs 109.9px，视觉饱满无下坠。

### 拖拽手感重做（用户反馈"拉一下一点点px就不行、整体粗糙"）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 小位移拖拽就"不行了" | 松手后固定 0.2s 即转回位，回位 slerp τ≈0.22s——手势半秒内被吞掉 | 惯性滑行阻尼 15→**3**（滑行 ~1s+），速度 <0.05 才转回位；回位 τ 0.22s→**0.5s**，总生命 ~3s |
| 拖着走图形"粗糙"散裂 | 拖拽时每个 pointermove 同时打进 wake 冲量（gain≤1.6）——旋转+猛烈局部涟漪叠加 | 拖拽期间 wake 停机（`event.buttons === 0` 才 push）：按压时玫瑰作为整体相干旋转，粒子不脱离等高线 |
| 回位突兀 | 惯性阶段与回位阶段是两个观感割裂的动作 | 惯性期间就以 τ≈1.25s 轻微吸引 home，滑行→回位为同一连续运动 |

实测时间线（12px 小拖拽 → ~7° 相干旋转）：+0.5s 仍处惯性 0.12rad → +1.2s 0.038rad → +2s 0.008rad → +3s 归位 idle。

### 对照 OpenAI 官方动效的最终检查（同日）

Astra 已解码的交互物理（`prog0.vert` `astraCoast`/`astraParticleMotion`）：位移回位 `exp(-age)`（**τ=1.0s**）、粒子速度上限 **0.5 NDC/s**（缓慢滑翔感）、冲量平方衰减权重、模拟总寿命 **6s**。对照结论：

- 本项目 wake 回位 τ=0.55~2.5s（质量分层）、寿命 3.2s——与官方同一家族，尾迹略短但观感一致；
- 官方粒子被推开后"带速度滑回"，本项目为"静态偏移指数回位"，视觉等效（偏移衰减即滑动），无需引入状态纹理模拟；
- 官方 bloom/构图语言（紧致亮核+有界光晕+少量暖星）此前已对齐；
- 拖拽旋转为本项目独有交互（官方场景不可拖），按"整体相干+绵长回位"设计并通过合成拖拽时间线验证。
