# Misaya Notes：布局、字体与滚动体验评审及改版建议

日期：2026-09-05。范围：线上首页、AI Algorithms 分类页、长程 Agent 文章页；同时核对本地前端代码，参考提交 `4a1f20f`。本次仅进行观察、分析和文档编写。

与 [Astra 粒子技术报告](/Users/yang/projects/ai-tech-blog/docs/astra-particle-galaxy-technical-report-2026-09-05.md) 配套使用：本报告决定页面如何组织与呈现，前一份报告负责粒子场景的技术方案。以下设计建议尚未实施，也未经用户审定为最终视觉稿。

## 1. 核心判断

**当前最影响观感的是主次竞争、空间分配失衡和字体风格与新目标不匹配。** 首屏同时承担巨大标题、分类介绍、阅读路径、搜索和最新文章；各区域都想解释网站，却没有形成一个明确的视觉中心。继续直接添加大面积粒子，会让原有冲突更加明显。

建议把方向调整为 **“现代研究站：有辨识度的首屏 + 清楚的内容索引 + 安静的长文阅读”**。首页负责吸引和定位，分类页负责选择，文章页负责理解。三种页面共享字体、色彩和间距规则，但不需要相同的装饰强度。

现有实现也有值得保留的基础：算法 / 应用两个内容方向明确，青色强调已经形成一定识别度，字体自托管、内容语言标记、键盘焦点和阅读进度条都已有实现。改版应在这些基础上重新分配视觉权重。

## 2. 观察方法与证据范围

桌面首页与分类页采用约 1440px 的浏览器视口观察，实际内容视口宽 1434px；手机布局采用 390 × 844 的设置，实际内容宽 384px。文章桌面样本的实际内容视口为 1274 × 720。数值来自 DOM 几何与计算样式，不能当作所有设备的固定尺寸。

本次观察了深色主题、英文界面以及中文文章混排，并进行了真实页面滚动。手机部分是窄视口布局观察，未模拟触屏硬件，也未进行真实手机 GPU、网络或帧率测试。浅色主题、完整中文界面、所有文章和全部交互流程不属于已实测范围。

本文把结论分成三类：**确认的问题**来自直接观察或源码；**视觉判断**是基于新方向的设计评价；**建议参数**需要在候选页面中继续调整。历史报告的通过记录不替代本次实际观察。

## 4. 推荐的视觉方向

推荐使用现有青色作为少量强调色，以清晰的无衬线大标题、原创科学图形和受控星系场景形成“研究与工程”的气质。背景采用近黑色与稍亮内容表面区分层级，避免所有东西都漂浮在同一块黑色上。

这里的“炫酷”应由三种高质量内容共同提供：首屏动态星系、精选文章的主题图、正文中的图表与公式。不要让每个按钮、卡片和章节都发光或旋转，否则视觉焦点会重新分散。

可以保留少量衬线用于文章引语或专栏标题，让网站保有个人气质。主导航、首页标题、分类与列表标题优先统一为无衬线。这个方向是针对你本次提出的新目标作出的建议，调整了前一份粒子报告中“沿用现有衬线大标题”的保守设想。

首页定位句可以先比较以下候选，仅供视觉验证，不替代已经发表的内容：

- 中文：**理解模型，构建智能。**
- 英文：**Understand models. Build intelligence.**
- 辅助说明：围绕模型机制、长上下文与 Agent 工程的研究和实践。

“AI 算法 / AI 应用”仍保留为内容入口。标题负责表达价值，分类负责组织文章。

## 5. 首页布局：建议的滚动顺序

**导航 → 品牌首屏 → 精选文章 → 两个研究方向 → 最近文章 → 作者与联系。**

这让读者依次回答：这是谁的网站、有什么值得看、怎样继续探索。每一段都有不同的任务和视觉形态。

| 区域 | 桌面布局 | 手机布局 | 与粒子场景的关系 |
| --- | --- | --- | --- |
| 导航 | 品牌左侧；精选 / 算法 / 应用 / 关于与搜索、主题、语言在右侧 | 品牌、搜索、菜单；次要设置进入菜单 | 始终清晰，避免粒子透入导航文字 |
| 首屏 | 简短标题与一行介绍占左侧约 5/12，星系占右侧约 7/12 | 标题、简短介绍、紧凑视觉区、阅读按钮 | 主体保留自己的空间，文本附近控制星点亮度 |
| 精选文章 | 一篇醒目图文组合：主题图、标题、两行摘要、日期 / 阅读时长 | 图文自然堆叠，尽早露出标题 | 进入此区时，星系减弱并退出主要视觉 |
| 研究方向 | 算法 / 应用并排，各有一句定位和少量代表主题 | 两个紧凑模块纵向排列 | 使用静态小图形建立识别即可 |
| 最近文章 | 3–5 条结构统一的文章行，配全部文章入口 | 标题优先，摘要和元数据逐级减弱 | 保持静态、便于快速扫读 |
| 作者 | 一句话研究方向、Scholar / GitHub / 联系入口 | 同样简洁 | 不再制造新的大型动效 |

建议起始尺寸：桌面内容最大宽度 1200–1280px，常规列间距 32–48px；移动端左右边距 20–24px。桌面大章节之间 72–104px，手机 40–56px。间距由内容层级决定，不为每个模块都强制占满一屏。

首屏连同导航可先以桌面 80–90svh、手机 75–90svh 做候选，并约束最大高度。目标是第一屏看到定位和主要操作，同时让下一段内容有清楚的露出。窄屏和横屏必须允许内容自然长高，不能用固定高度裁剪长中文标题。

新的粒子场景需要先获得空间：现有右侧已经被双轨目录占满，不能简单叠加。先用静态占位确定版面，即使动画暂停，整页也应成立。

## 6. 字体：调整角色比不断增加字体更重要

当前使用 Fraunces / 宋体做显示和阅读，Instrument Sans / 黑体做界面，JetBrains Mono 做代码。这是一套明确的“研究笔记”选择，不能把字体文件本身当成缺陷。但它与现在期望的科技发布页观感有距离，尤其是 92px 的厚重衬线英文与右侧较小的中文信息并列时。

推荐先利用已有的 Instrument Sans，将其提升为主显示字体，再比较是否还需要新增字体。这能减少下载和接入成本。中文使用明确的黑体回退，代码保留 JetBrains Mono。

| 字体角色 | 建议字体方向 | 桌面起始值 | 手机起始值 |
| --- | --- | --- | --- |
| 首页主标题 | Instrument Sans + 中文黑体，字重 550–650 | 英文 64–80px；中文 56–68px | 英文 38–46px；中文 34–42px |
| 文章页标题 | 与列表一致的无衬线，字重 600–650 | 36–44px | 28–34px |
| 章节标题 | 无衬线，字重 550–650 | 28–32px | 23–28px |
| 文章列表标题 | 无衬线，优先保证完整内容 | 22–26px | 20–23px |
| 正文 | 黑体为默认候选；与现有宋体做同文 A/B | 18–19px | 17–18px |
| 元数据与导航 | Instrument Sans + 中文黑体 | 14–15px | 14px 起 |
| 代码 | JetBrains Mono | 14–15px | 13–14px，代码块允许横向滚动 |

这些是调参起点，不是所有语言共用的硬尺寸。英文显示标题可有轻微负字距，中文避免机械套用；中文正文行高先比较 1.75–1.85，英文约 1.6–1.7。

文章当前中文段落约 18px、行高约 32.7px、行宽约 647px，这部分已经接近可用的阅读尺度。不要因为首页需要更强视觉，就把长文也改成宽屏巨大字号。中文正文建议保持约 32–38 个汉字的行宽；英文段落约 60–72ch，图片与代码可以适当突破正文列宽。

对字体的验证必须使用真实内容：长中文标题、英文技术名词、数字、括号、数学符号和粗体混排。计算样式列出的字体栈不等于所有系统最终选中的实际字形，本次没有验证 Windows、Android 的字体回退。

## 7. Scroll：从滚动手感到阅读节奏

### 7.1 保留自然滚动

第一版保留浏览器原生滚轮、触控板与触屏行为。先把内容顺序和节奏做好，再判断是否有必要引入平滑滚动库。当前代码中没有发现 Lenis / GSAP 依赖；现有部分锚点通过 `scrollIntoView` 平滑跳转。

`scroll-behavior: smooth` 主要影响导航或 API 触发的滚动，不会把用户滚轮操作自动变成惯性滚动。[MDN 的说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-behavior) 明确区分了这两类行为。后续不能只加一个 CSS 属性就宣称完成了滚动体验改造。

### 7.2 首屏运动脚本

以下进度是“首屏开始离开视口，到首屏完全离开”的局部进度，属于设计候选：

| 首屏离开进度 | 内容行为 | 粒子行为 |
| --- | --- | --- |
| 0–20% | 标题和按钮保持稳定，读者可以随时操作 | 缓慢自动运动；允许轻量交互 |
| 20–65% | 标题随页面自然上移，精选文章逐渐出现 | 微小姿态变化，适量扩散和亮度衰减 |
| 65–100% | 精选文章成为主要内容 | 柔和淡出，完全离开后停止绘制 |

不建议为了一个首屏动画强制让用户滚动两三整屏，不做滚轮速度劫持或强制逐屏吸附。用户快速下滚时，应立即到达内容；动画跟随进度，不要求先播放完毕。

### 7.3 内容区动画

章节首次进入视口，可使用约 12–20px 的位移与 300–450ms 的轻淡入；并列项目错开约 50–70ms，整个组不超过约 650ms。按钮反馈约 140–180ms，卡片悬停只需轻微边框 / 表面变化，必要时最多 2–4px 位移。

正文段落保持静态，不逐段重新出现，不用大幅缩放。图片和图表是否有动画应取决于表达内容，而不是套用统一的入场模板。尽量以 transform / opacity 承担 UI 动画；这通常比逐帧改变布局尺寸更易控制性能，仍需实测。[web.dev 动画指南](https://web.dev/articles/animations-guide)

### 7.4 导航、目录与返回

首页和分类页可采用 64px 左右的稳定吸顶导航，向下滚动后仅增加轻微底色与分隔线，不在滚动中不断改变高度。文章页使用更克制的阅读工具条，提供返回、目录和可选的文章内搜索。

桌面文章目录应在正文期间保持可见，超长目录只在自己的区域内滚动；当前章节使用明确但安静的高亮。手机用可展开目录，选中条目后收起。锚点位置要避开导航，并保持地址可分享。

**已确认目录问题的定位线索：** `.paper-toc-rail` 的采样高度与内部 sticky 面板相同，外层本身为 static；滚动后两者一起离开视口。修复时应检查目录应由哪一层 sticky、网格对齐方式、父容器高度和祖先 overflow。这些是明确的检查方向，尚未通过修改验证唯一根因。

另一个源码问题是 [文章锚点函数](/Users/yang/projects/ai-tech-blog/client/src/pages/PostDetail.tsx:421) 显式传入 smooth，函数本身没有依据减少动态效果偏好分支。后续应在 JavaScript 调用处一并处理，不能只依赖全局 CSS。系统偏好开启或用户暂停时，应提供静态可用状态；持续自动动画也要能暂停。[W3C 动态内容控制说明](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)

文章跳转与浏览器返回需要单独验证：从列表进入文章应有可预期的起始位置，返回列表尽量恢复原位置，目录锚点与返回键不能互相干扰。本次没有完成这组往返行为验收，先列为改版要求。

## 8. 文章卡片、分类页与阅读页

### 8.1 文章卡片

当前文章行横跨很宽区域，标题靠左、Read more 靠近最右端，元数据之间还有多个图标。建议统一为“主题图 → 分类 → 标题 → 一句话摘要 → 日期与阅读时长”。浏览量作为次级信息或省略，不与标题竞争。

精选文章使用较大且具有主题意义的图形；普通列表可采用约 120–160px 宽、3:2 比例的缩略图。手机可缩小为约 80–96px，或者将次要列表做成纯文字。既然有图片，就让它能表达文章主题；不要保留几乎辨认不出内容的暗色小图，也不要让多个不相关主题共享同一张示意图。

整行 hover 可以给出细微反馈，但不宜出现强烈大边框或大幅浮起。标题本身应是清楚的链接，整行可点击时要避免多重嵌套链接。首页的代表文章与最近文章尽量去重。

### 8.2 分类页

本次算法分类页从标题、长介绍、机制说明、主题串、统计数字，到 Reading paths，占用了很长的前导区域。全部文章标题约在 y=1229 才出现；更上方的路径卡片已有文章链接，因此不能说之前完全没有阅读入口。

建议压缩为：标题 + 一句定位 → 紧凑的主题 / 路径选择 → 文章列表。对于当前体量，无需把只有一篇文章的每条路径都包装成很高的展示卡。真正具备多篇顺序关系的系列，再提供展开的阅读路线。

保留“按路径阅读”和“查看全部”的能力，但让文章数量、浏览量等统计回到次级位置。分类页应比首页更快进入内容，避免复制一个大型首屏。

### 8.3 阅读页

优先处理公式渲染与目录滚动。随后简化文章外层大边框、阅读导引小框、分割线和标签群，让标题、摘要、正文自然连续。摘要可作为一段轻底色导语，无需叠加多种玻璃效果。

当前阅读字号和正文列宽值得保留为基准。下一轮重点比较黑体和宋体在长篇中英技术混排下的效果，而不是同时改变字体、字号、行高、列宽后再猜原因。

公式应该使用正常数学排版；代码块提供清楚的语言标记、复制入口和局部横向滚动；宽表格与图片独立处理溢出。文章底部收敛为相关 / 下一篇和作者信息，避免重复堆放多组回到分类的按钮。

右下角博客助手保留为可发现的次级入口。手机应考虑底部安全区，并给正文结尾留出足够空间，防止遮挡链接或正文。不要再额外叠加常驻的大型“回到顶部”按钮与助手争夺同一区域。

## 9. 色彩与页面层级

可先尝试一组近黑底、稍亮表面和青色强调的配色关系，例如背景接近 `#080B10`，内容表面接近 `#11171F`，主要文字接近 `#EDF2F7`。这些是视觉候选，不是已测量通过的最终 token；浅色主题要单独设计与验证。

重点是为底、内容、强调建立可辨认的关系。只有导航浮层、弹出菜单等少数地方需要模糊；正文和大面积文章卡片可用稳定实色。光晕留给主视觉，高亮色用于主要行动和当前状态。

正式验收时，应在实际渲染背景上检查文本对比度，尤其是粒子经过文字背后时。普通文字通常要求至少 4.5:1，大字通常至少 3:1；本次没有重新进行全站像素级对比度测试，不据肉眼宣布通过或失败。[W3C 文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
