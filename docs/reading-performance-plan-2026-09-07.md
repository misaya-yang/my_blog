# 阅读性能优化方案与首批结果

## 目标

分别解决下载等待、主线程阻塞与视觉跳动。保持当前星系风格、文章完整内容、公式与代码、正文/目录联动和键盘焦点；不以隐藏内容、取消特效或破坏长文定位换取分数。

本方案分清「已落地」「下一阶段待实施」和「尚未测量」。当前改动是首批优化，不能解释为性能任务已经全部验收。

## 已确认的成本

1. 正文接口完成后才触发 Markdown 渲染器下载，造成串行等待；KaTeX 和高亮样式在渲染之后才导入。
2. 代码高亮默认携带大量常用语言，而现有文章主要使用 Python、TypeScript 与纯文本。
3. 粒子初始化早于正文，首次 WebGL 工作与长文解析/布局竞争主线程。
4. 即使 WebGL 正常，也下载约 200–300KB 的旧静态后备图。
5. 首页为列表/预览获取多篇全文；相关文章链接也返回邻近文章正文。
6. 复制按钮的反馈放在文章页状态中，触发整篇 Markdown 再解析。
7. 原性能上报对所有条目使用 startTime，事件发生时刻被当成耗时，布局偏移值也不正确。

## P0：首批优化 — 已完成

| 工作 | 实现 | 验收 |
| --- | --- | --- |
| 打断依赖串行等待 | 进入文章路由就并行下载 Markdown/KaTeX/样式；样式随渲染模块加载 | 生产构建和长文直达正常，公式不等待渲染后的 CSS 请求 |
| 缩减高亮 | 注册 Python、JS、TS、JSON、Bash；纯文本和未支持语言保持转义后的可读源码 | TS 高亮、未知语言回退、HTML 转义测试通过 |
| 正文优先 | 首次文章加载先等待正文节点，再安排空闲时段初始化星场；兼容无 idle API 的环境 | 本地观察到正文节点先出现、Canvas 随后就绪；跨页仍复用场景 |
| 后备媒体按需加载 | 只在模块/WebGL 失败或上下文丢失时设置后备图地址 | 正常 Canvas ready 时 poster src 为空 |
| 公开内容复用 | 首页与公开文章缓存 60 秒，避免窗口焦点造成重复请求；私有/草稿正文不套用公开缓存策略 | 保留原权限判断与编辑端默认接口语义 |
| 首页响应瘦身 | 显式 summaryOnly 模式保留摘要、阅读时长及前三个小节；默认接口仍返回全文 | 同一批 9 篇文章由 175,158B 降至 21,017B，约减少 88% |
| 关联链接瘦身 | 仅返回 id、slug、title | 本地资源样本从约 102KB 降至约 1KB；接口契约测试覆盖 |
| 复制反馈局部化 | 复制状态与定时器放在按钮组件内 | 手机代码 scrollLeft 在复制前后均为 68.5px，反馈正常 |
| 清理无效资源 | 移除已不参与当前排版的 Fraunces 字体预加载 | 保留当前 Source Sans 3 与中文回退 |
| 修正测量单位 | event 使用 duration；layout-shift 使用 value 并排除近期输入；无统计配置时不启动观察 | 原始样本明确标记 raw，不冒充 INP/CLS 聚合指标 |

## 本地证据与边界

长文样本：`/post/llm-rl-post-training-verifiable-rewards`。使用内置浏览器、原生 PerformanceObserver 与短期探针，探针最终已移除。

| 环境/样本 | 正文标题节点出现 | 星系 ready | 最长任务 | 8 秒采样窗内阻塞量 |
| --- | ---: | ---: | ---: | ---: |
| 开发环境，改动前 | 785ms | 226ms | 116ms | 136ms |
| 开发环境，首批改动后 | 733ms | 903ms | 102ms | 86ms |
| 本地生产静态资源预览 | 666ms | 860ms | 92ms | 72ms |

阻塞量是该采样窗内 `sum(max(task.duration - 50, 0))`，不是 Lighthouse 标准 TBT，也不是 INP。正文节点出现不等于 LCP 或全部公式完成绘制。样本未做 CPU/网络限速，浏览器缓存、开发构建与数据库响应有波动，不能据此计算稳定的整体性能提升比例。

生产静态资源预览使用构建后的前端，API 代理到本地开发服务；它不是线上生产测试。最后一个样本仍包含正文挂载附近的 92ms 与粒子开始附近的 80ms 长任务，尚未通过调用栈精确归因。

构建中的 Markdown 专属模块由约 176KB（gzip 54KB）降至约 48KB（gzip 16KB）。这是该模块的缩减，不是整站 JS 的缩减。KaTeX 和 Three.js 本身仍是较大的资源。

## P1：消除剩余长任务 — 下一阶段，待实施

1. **先定位调用栈。** 对同一长文做 4 倍 CPU 限速的录制，区分 Markdown AST、KaTeX、React commit、浏览器 layout 和 WebGL shader 编译。记录中位数及较慢样本，禁止仅按任务出现时间猜原因。
2. **按占比选择实现。** 若公式转换占主导，评估 Worker 生成安全 AST/公式结果并缓存；若 DOM/layout 占主导，再试分段提交或屏外内容渲染。必须保留全文查找、脚注、跨段引用、文本选择、锚点刷新与目录联动。
3. **粒子初始化。** 测试 Three.js 异步 shader 预编译、首帧分阶段上传；处理卸载/上下文丢失和取消。仅在实测收益成立时启用，避免把一次卡顿改成持续抖动。
4. **阅读期预算。** 以正文滚动和输入优先；若粒子拖低交互响应，再做设备质量分档。保留当前形态与色彩，先降像素密度/非关键拖尾开销，再考虑粒子数量。

验收：相同设备与网络下，最长关键任务明显下降；加载期间菜单、滚动、复制可操作；不丢失焦点和阅读位置。目标是把可拆分的关键任务控制在 50ms 内，但这是工程目标，当前尚未达标。

## P2：持续减少下载与接口等待 — 待实施

- 查清关联信息接口 1.5–4 秒波动的数据库/连接池原因。数据已缩小，不能再把全部等待归因于传输体积。
- 评估首页/分类索引的 SQL 投影和版本化公共索引缓存；任何缓存必须在发布、更新、隐藏文章时失效，不缓存私有正文。
- 审计约 478KB 原始 CSS 中公共/编辑/管理规则依赖，逐页拆分。先验证深浅主题、hover/focus 再移除旧规则，不一次性删除覆盖层。
- 检查部署端静态资源压缩与不可变缓存、正文接口缓存头、字体子集及重访请求量；本轮没有修改部署或线上缓存。

## P3：验收矩阵与防回退 — 待执行

- 生产构建，冷启动/重访分别测；1440、1280、390、320 像素；深浅主题；慢 4G 与 4 倍 CPU 限速；至少一台较弱的实体手机。
- 路径：首页→文章→另一文章→返回；长文快速正反向滚动；目录跳转；代码复制/横向滚动；加载中打开菜单；失败后重试。
- 每种关键场景至少五次；记录资源大小/请求链、最长任务、交互延迟和布局偏移。另做现场数据聚合，不把实验室样本当成真实访客第 75 百分位。
- 线上目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，按移动端/桌面端分别看第 75 百分位。这些目标依据 [Web Vitals 官方说明](https://web.dev/articles/vitals)，当前尚未完成线上验收。
- 建立包体积预算与固定长文回归，重点防止默认全语言高亮、后备图重新抢带宽、复制/目录变化重渲染全文。

## 本轮验证

相关前后端测试、TypeScript 和生产构建；浏览器检查长文加载、菜单操作、代码复制位置保持、首页摘要和小节预览、正常 WebGL 不下载后备图。未部署，未把临时测量脚本保留在产品中。P1–P3 是后续任务，不能标记为已完成。
