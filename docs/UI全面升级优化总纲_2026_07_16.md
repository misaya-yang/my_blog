# Misaya Notes 全面 UI / Motion 升级优化总纲

日期：2026-07-16
执行分支：`dev_0716`
模式：`motion-landing-page-builder` Upgrade Mode
状态：两轮实现、走查与发布前门禁均已完成（2026-07-18 增量复验）

## 1. 核心目标

本轮不是重新设计一个通用 AI SaaS 站点，而是在现有产品、内容、路由和技术栈不变的前提下，对 Misaya Notes 做一次完整、可验证的 UI 升级：

1. 保留“深色研究笔记 / research cockpit”的作者身份。
2. 消除 orbit hero、悬浮玻璃卡片群、助手剧场、重复导流等模板化 AI 视觉信号。
3. 让首页更像研究索引，让文章页更像可信技术出版物，让 Agent 更像安静伴读工具，让 Owner 工具更像高效工作台。
4. 建立统一的排版、边界、表面、交互状态和动效预算。
5. 覆盖全部实际路由、全局 Blog Agent、加载/空/错/鉴权等关键状态，不只修改首页截图。
6. 修复走查中确认的前端正确性、响应式和可访问性缺陷。
7. 通过同视口 before/after、自动化检查和真实浏览器走查证明升级有效。

## 2. 不可破坏的产品约束

- 不改变现有公开路由、slug、SEO、认证、数据库和 API 合同，除非为修复已确认缺陷所必需。
- 不替换 React、Wouter、Tailwind、Radix、现有 CSS 分层或现有 motion 能力。
- 不增加新的动画依赖；简单入场和交互反馈使用 CSS，复杂状态继续使用现有组件能力。
- 不重写文章、导航、标签、分类和产品文案。
- 不增加虚假指标、装饰性 badge、通用 bento、紫蓝渐变、发光 blob 或新的 orbit/星球系统。
- 不让每个信息组都成为有边框、有背景、有阴影的卡片。
- 不以 hover 作为唯一可发现性或状态反馈。
- 公共阅读页、Agent、Owner 工具必须保持各自用途，但共享同一套语义 token 和品牌基因。
- 所有非必要动效必须提供 `prefers-reduced-motion` 的完整静态结果。
- 当前 CSS 债务不得增长：`!important`、viewport 字号和 broad selector 至少不高于本轮基线。

## 5. 统一视觉系统

### 5.1 视觉命题

主命题：**Editorial Signal Ledger / 研究信号账本**

页面应像持续维护的技术研究索引和出版物：

- 排版、对齐、留白和细分隔线承担结构。
- 青色只用于链接、焦点、选中和关键状态。
- 阅读 serif 与 UI sans 明确分工。
- 暗色不是纯黑，亮色不是纯白。
- 普通内容保持开放；只有输入、浮层、模态、选中项和密集数据获得持久边界。

### 5.2 支持性视觉母题

1. 一条细的“研究信号线”：用于 page hero、section heading、当前 TOC，不扩展为装饰图案。
2. ledger / hairline：用于文章列表、时间线、路径和 Owner 数据。
3. compact marker：用于状态、路径、来源编号和选中项。

### 5.3 删除或压低的视觉信号

- 首页 orbit 背景图及文字叠图。
- 星图、发光、模糊层作为主要身份。
- 每组内容都加 surface、border、shadow。
- 长期常驻的 “Blog Agent” 文字 pill。
- 面板内层层嵌套的 scope / trust / quota / prompt 卡片。
- 文章首屏高对比 “Main claim” 机器摘要卡。
- 文末两套连续的 “After reading / Continue reading”。
- Owner 页面大面积玻璃、hover 才出现边界、整块 dock 缩放。

### 5.4 交互状态合同

所有重要控件至少具备：

1. rest：安静但可发现；
2. hover：仅 fine pointer，轻微 tonal shift 或最多 1px 位移；
3. focus-visible：明确 outline，不依赖阴影；
4. pressed：回落到画布；
5. selected / expanded：持久填色、marker 或文字对比；
6. disabled：语义和视觉同时成立；
7. touch：不依赖 hover；
8. reduced-motion：不隐藏内容、不保留无意义位移。

## 6. Motion 合同

全站 motion intensity：3/10。

| 场景 | 目的 | 合同 |
| --- | --- | --- |
| 公共路由进入 | 建立阅读顺序 | 280–360ms，opacity + 4–8px Y，正文和 CTA 在 DOM 中立即可用；reduced motion 直接显示 |
| 首页层级 | 先作者/标题，再最新文章，再研究路径 | 60–90ms 轻 stagger，总时长不超过 620ms |
| 控件 hover/focus | 反馈 | 140–180ms，颜色/背景/边界，最多 1px；仅 fine pointer 有 hover lift |
| pressed | 确认操作 | 80–100ms，回落画布 |
| TOC active | 阅读定位 | marker 与文字颜色 160ms；不自动滚动 TOC |
| Agent open/close | 说明工具来源 | desktop 200/150ms；tablet/mobile 220/160ms；中断反转，不叠加 timer |
| Editor/Preview | 模式切换 | 120–150ms opacity，不做大幅滑动 |
| 保存状态 | dirty/saving/saved/error | 160ms 文案/图标交叉；最新 mutation 胜出 |
| code copy | 操作确认 | 120ms 图标切换，2s 后恢复；新操作取消旧 timer |
| streaming | 显示检索进度 | 120ms 状态文案更新，不做循环 AI 剧场 |
| row mutation success | 结果可见 | 400–600ms 低饱和 tonal highlight，不弹跳 |

禁止：

- scroll hijack
- 大段 parallax
- pinned narrative
- 持续循环装饰动画
- 大面积 blur/filter/shadow 动画
- 所有 section 同时 reveal

## 7. 响应式总合同

### 7.1 Desktop 1440

- 公共容器保持编辑感，避免内容横跨 1400px 形成空洞。
- 首页左右两栏不再共享 orbit 背景；标题与路径各自有明确阅读顺序。
- 文章正文 66–74ch，TOC 约 15rem。
- Owner Manage 使用任务优先结构；Editor 可三 pane。
- Agent 最大 360–400px，不覆盖正文矩形。

### 7.2 Tablet 768

- 不能继续使用压缩的 desktop 双栏。
- TOC 改为 inline details。
- Editor 使用单 pane Editor/Preview。
- Manage 不显示 980px 宽表格。
- Manage Agent 使用 3×2 工具入口或紧凑选择器。
- Agent 使用 modal drawer，锁背景滚动并使背景 inert。

### 7.3 Mobile 390

- Header 保持 72px，控件实际触摸尺寸 ≥44px。
- 有用内容在装饰/统计之前。
- 首页首屏不出现 orbit 图，标题、最新文章和搜索依次可见。
- Archive summary 使用紧凑 2×2 或开放 ledger，不连续堆四张卡。
- 文章首段 Y≤500px。
- Editor 为真实 Editor/Preview 模式切换。
- Agent sheet 位于 Header 下方，考虑 safe area，不覆盖 Header。

### 7.4 Short height / 320 reflow

- viewport-height section 不能裁切 CTA。
- Agent composer 固定，消息区独立滚动，不保留 420px 硬最小高。
- code/table 允许内部二维滚动，页面本身不能横向滚动。

## 8. 逐页实施合同

## 8.1 Home `/` — P0

文件：

- `client/src/pages/Home.tsx`
- `client/src/styles/visual-refresh.css`
- `client/src/components/ArticleCard.tsx`

当前问题：

- orbit 图片位于整个首屏右侧并与 track 文本叠加，是最强 AI 模板信号。
- 标题、最新文章、3 个统计、搜索、两条 track 同时争夺首屏。
- desktop 首屏横向信息过多；mobile 虽已上移内容，但仍像连续模块堆叠。
- track 内又包含路径、文章、topics，层级密度偏高。

方案：

- 删除首页 orbit 背景图和文字叠图，恢复开放画布。
- 首屏由内容决定高度，不再使用接近满视口的 `min-height` 把 “More notes” 推远。
- 标题与作者定位为第一读；最新文章是第二读；研究路径是第三读。
- 将统计降级为一句开放式摘要或一行轻 ledger，不作为三张独立卡。
- 搜索保留明确边界，但不使用发光或渐变 CTA。
- mobile 搜索保持单行输入与 44px 图标提交，不使用整行高饱和按钮。
- Track 改为 editorial band：标题、摘要、主路径、代表文章形成单一层级。
- topics 在 mobile 只保留最关键 2–3 个或横向滚动，不挤压正文。
- “More notes” 使用扁平 ledger，不形成卡片岛。
- FeaturedNote 移除误用的 `article-card` class，避免共享样式污染和审计误判。

验收：

- 1440×900 第一视口只有一个主要视觉焦点。
- 390×844 标题、最新文章、统计/搜索的阅读顺序清楚。
- 1440 的 `.home-featured-note-body` 顶部 ≤460px，`#research-index` 顶部 ≤980px。
- 390 的 Latest note 顶部 ≤420px、搜索 ≤700px；研究索引在完整两条 Track 之后且顶部 ≤2100px。
- 不再加载、请求或展示 `research-orbit-hero.jpg`。
- 首页动画总序列 ≤620ms。
- 无横向溢出，现有链接和搜索行为不变。

## 8.4 Search — P1

文件：

- `client/src/pages/Search.tsx`
- `client/src/styles/visual-refresh.css`

方案：

- query input 始终是主操作。
- 默认无查询态也使用紧凑 query hero，不展开为传统 landing hero。

验收：

- 空搜索、无结果、有结果、错误状态均可辨认。
- 390 的主恢复动作在首屏可见。
- 长 query 和中文标题不溢出。
