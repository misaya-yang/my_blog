## 1. 结论

你的记忆基本正确：**官网星系确实使用 Three.js，当前画布直接标注 `three.js r180`。** 页面存在实时绘制的 Canvas、独立的拖拽交互层、滚动形态配置和静态后备图。WebGL 2 是与现有证据最一致的渲染路径，但本次没有抓取实际 GPU 上下文，不能把它写成直接测得的结果。

它的视觉特点是：**把具有设计感的轮廓变成有空间厚度的星点，再结合亮度层级、冷暖配色、柔和光晕、缓慢运动与滚动变形。** 首屏素材的替代描述明确提到数字 6；实际滚动到另一章节后，观察到了由星点组成的光标轮廓。因此，只做一个均匀随机旋转的星空，会遗漏这个设计最有辨识度的部分。

对博客的建议是：采用 **React + 独立 Three.js 场景 + 自定义粒子材质 + CSS 氛围层**，先交付有吸引力的首页首屏，再决定是否扩展滚动变形。沿用现有 Vite、主题和文章体系即可。效果运行在读者设备的 GPU 上，本身无需调用大模型，也不消耗模型 token。

## 3. 画面为什么有这种质感

| 视觉组成 | 观察到的特征 | 复现时应关注什么 |
| --- | --- | --- |
| 主体轮廓 | 螺旋带、环状回转和明显留白；首屏后备图描述指向数字 6 | 先设计轮廓，再分布粒子；保留负空间和不对称构图 |
| 星点层级 | 大部分点细小黯淡，少量星点强烈发亮 | 使用偏向小尺寸、低亮度的分布，避免每颗星都同样显眼 |
| 冷暖关系 | 蓝白、白色为主，少量暖橙星点穿插 | 色彩服务深度和焦点，不做均匀彩虹分布 |
| 空间厚度 | 星带有散布和前后层次，局部像颗粒云 | 给轮廓有限厚度与深度；避免把全部点放在同一平面 |
| 高光与光晕 | 亮星有清楚的中心和柔软外缘，核心区域明亮 | 核心与外晕分开控制，防止整幅图被模糊成一团 |
| 空间背景 | 稀疏远景星点、深色底、偏蓝氛围、外围暗角 | 背景层应衬托主体，文字附近保留低亮区域 |
| 运动节奏 | 自动变化与可交互形态；滚动后出现光标 | 限制速度、平滑状态转换，避免突然跳变 |

“像照片一样的散景”不必依赖真实景深。不同大小的软粒子、有限的深度衰减和少量发光点，就可以产生类似视觉线索；只有在基础画面已经好看时，才值得比较额外景深或 Bloom 的收益。

## 4. 已确认的页面分层方式

浏览器里看到的结构可概括为：

**黑色背景 → 实时粒子 Canvas → CSS 氛围渐变 → CSS 暗角 → HTML 标题与内容 → 专用交互区域。**

背景容器固定在视口，设置为不接收指针事件。交互交给另一层透明按钮，标题和正文仍是普通 HTML。这种职责分配有利于保持文字清晰、可访问，并让动画背景与网页布局分开管理。

CSS 氛围层使用径向渐变，配合 `mix-blend-mode: plus-lighter`。本次读取到的配置包括基色 `#23435F`、目标透明度 `0.55`、入场时长 `5.5s`。外层暗角在中心约 47% 范围内保持透明，在外围逐渐加深。**这些是 CSS 合成参数，不是粒子的混合模式、Bloom 强度或相机设置。**

Canvas 还带有随页面状态变化的横向遮罩；标题有单独的位移变量。说明官网也在处理内容与背景的衔接，不能把整个设计简化为一个孤立的全屏 Canvas。

## 5. 推荐给博客的实现方式

### 5.1 技术选择

| 方案 | 适用情况 | 本项目建议 |
| --- | --- | --- |
| React 内封装 Three.js | 首页有一个独立粒子场景，需要明确控制生命周期和资源 | **首选**：依赖与职责最直接 |
| React Three Fiber | 后续需要大量可组合 3D 对象、多个交互场景 | 可作为扩展选择，本次没有必要先引入完整生态 |
| 原生 WebGL | 极端包体目标，且愿意承担渲染器维护 | 当前收益不足以抵消实现复杂度 |
| WebGPU | 需要显著更复杂的计算或巨大规模模拟 | 暂无需求驱动 |
| 视频 / 静态图 | 固定镜头展示，或低性能设备与失败后备 | 静态图应保留；视频不满足自由旋转的同等目标 |

后续实施时选择经过兼容性验证的 Three.js 版本并锁定依赖；`r180` 是本次官网观察值，不是博客必须使用的版本。

### 5.2 场景管线

| 阶段 | 输入与工作 | 输出 |
| --- | --- | --- |
| 形态准备 | 设计螺旋曲线、采样密度和可选品牌图案 | 稳定、可重复的目标点集 |
| 粒子准备 | 为每个点分配位置、尺寸、亮度、颜色、随机种子 | 一组紧凑的 GPU 属性缓冲 |
| 每帧更新 | 更新少量时间、进度、旋转和质量参数 | 提供给着色器的 uniforms |
| 顶点阶段 | 插值形态、计算漂移、转换到相机空间 | 屏幕位置与粒子大小 |
| 片元阶段 | 绘制亮核和柔和外晕，输出颜色与透明度 | 粒子图像 |
| 可选后处理 | 对亮部增加受控泛光并完成色彩输出 | 最终 Canvas |
| 页面合成 | 叠加暗角、文字保护区和现有内容 | 可读、可交互的首页 |

Three.js 的 [BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html) 支持用缓冲保存顶点及自定义属性；[Points](https://threejs.org/docs/pages/Points.html) 可用于批量绘制点云；[ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html) 提供自定义顶点和片元着色器入口。这些是建议管线的技术基础。

### 5.3 粒子几何：先解决“形”，再增加“量”

如果只做自然星系，可用螺旋曲线作为骨架。例如以半径 r 定义角度 θ，再在三维空间加入带宽和厚度。对数螺旋的一种表达是 θ = θ₀ + k·ln(r/r₀)，r₀ 必须大于零以避开中心奇点；中心星团单独采样。该公式是候选构造方式，不是官网算法。

但想接近官网的数字或图标效果，**更适合从原创矢量路径或手工调好的曲线采样**：

1. 确定主轮廓与空洞，沿弧长分配粒子，避免曲线参数导致局部拥挤。
2. 在曲线法线方向加入不均匀带宽，在深度方向加入少量散布。
3. 局部增加密度、扰动和亮星，让轮廓既能辨认又有星云质感。
4. 另建稀疏背景星点和中心亮区，分别调整亮度。
5. 固定随机种子，使刷新、截图对比和调参可重复。

博客可用一个原创螺旋或双星流呼应“算法 / 应用”两个方向。首版无需变成字母或 Logo；先把稳定构图做好。以后若增加品牌形态，应使用自己的符号和素材。

### 5.4 粒子的画法与发光

细星优先使用少量 Points 对象批量绘制，不给每颗星创建独立 React 元素或独立球体 Mesh。特别大的亮星可使用少量朝向相机的四边形，避免依赖设备对点大小的不同上限。

自定义材质主要负责三件事：透视下的尺寸变化、软边亮核、受控闪烁。可以用基于距离的指数衰减形成外晕，用更窄的曲线形成亮核；亮度和尺寸需要分别调节，防止远处的高亮星错误地变成巨大光斑。

第一轮先比较两种效果：

| 光晕方式 | 好处 | 代价 |
| --- | --- | --- |
| 粒子内部直接绘制亮核与外晕 | 可控、管线简单，不增加整屏模糊链 | 大光斑仍会增加透明像素绘制量 |
| 亮粒子 + 低分辨率 Bloom | 亮星周围更自然地扩散，便于统一调光 | 增加渲染目标、模糊与合成成本 |

推荐先完成粒子内发光，再用同一画面 A/B 比较 Bloom，保留视觉收益明确的一种。官方 [UnrealBloomPass](https://threejs.org/docs/pages/UnrealBloomPass.html) 是可选组件；本次没有确认官网使用它。

加法混合适合发光星点，但可能让密集区域过曝；透明粒子通常需要谨慎设置深度写入。色彩应在线性空间进行合理计算，再按输出流程转换，避免重复 gamma 修正或重复色调映射。相关原则见 [Three.js 色彩管理](https://threejs.org/manual/en/color-management.html)。

### 5.5 运动与交互

自动运动以缓慢旋转、少量局部漂移和弱闪烁为主。随机数应在初始化时生成；逐帧更新少量 uniforms，避免在 React state 中逐颗更新位置。

交互采用独立输入控制器：鼠标或触控位移形成目标姿态，渲染循环平滑追踪；使用时间步长计算阻尼，避免高刷新率设备上速度改变。限制旋转范围，防止用户把主体翻到看不见的位置。提供方向键、暂停和重置入口，并给操作区明确的名称与焦点样式。

手机上优先保留纵向滚动与双指缩放，只在明确定义的区域处理合适的拖动手势。首版不必加入粒子逐点拾取、鼠标排斥力或多指复杂操控。

### 5.6 滚动变形：第二阶段扩展

官网配置显示了滚动 cue 与多种形态。一个适合博客的候选方案是，为同一批粒子准备 A、B 两套目标坐标，以平滑后的滚动进度 s 插值：p = (1−s)·pA + s·pB，再叠加少量运动。

难点在于点的对应关系。直接将两个随机点集按下标连接，会产生大量穿越中心的轨迹。应在准备阶段按轮廓进度或空间分区建立对应，让星流转换保持连贯。散开强度、流速、主体透明度和相机姿态可以使用不同曲线，避免所有效果同时启动。

建议博客先采用“首屏聚合 → 向下阅读时减弱并散开”这一种转换。全站多形态叙事属于后续可选工作。

## 7. 性能与降级设计

以下是**起始预算**，不代表官网测量结果，也不是任何设备上的帧率保证。

| 项目 | 桌面候选 | 移动端候选 | 静态后备 |
| --- | --- | --- | --- |
| 粒子数 | 12,000–30,000 | 3,000–8,000 | 0 |
| 有效像素比上限 | 1.5；验证后再考虑 2 | 1–1.25 | 不适用 |
| 运动目标 | 60 fps；不稳则降档 | 30 fps 起步 | 无循环 |
| 光晕 | 粒子内发光，选配半宽半高 Bloom | 优先粒子内发光 | 已烘焙图像 |
| 交互 | 拖动、方向键、暂停 / 重置 | 简化手势、暂停 | 保留正常内容操作 |
| 场景不在使用中 | 暂停渲染 | 暂停渲染 | 无额外工作 |

像素填充成本常比“粒子个数”更重要。比如同一画面 DPR 从 1 变为 2，像素数变为 4 倍；再叠加大面积透明光斑和整屏模糊，GPU 成本会继续增加。将 Bloom 的宽高都降到一半，其单张目标像素数约降到四分之一，但总成本仍取决于通道、缓冲与处理次数。[MDN WebGL 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices) 支持减少绘制开销、控制分辨率和管理资源这些方向。

性能下降时，先判断瓶颈：填充 / 后处理受限时降低像素比、模糊分辨率和光斑大小；顶点 / CPU 受限时减少粒子或初始化工作。不要只凭设备型号决定高低档，也不要频繁升降档造成跳变。

必须实现的生命周期行为：

- 优先展示正常首页和固定尺寸后备图，再按需加载渲染模块；准备好第一帧后交接，避免黑屏与布局抖动。
- 页面隐藏、展示区完全离开视口、用户暂停时停止循环；恢复时限制异常大的时间差。
- 处理 WebGL 初始化失败和上下文丢失，回到可阅读的静态页面。
- 遵循系统减少动态效果偏好，并提供网站内可操作的暂停入口；静态状态无需启动持续渲染。系统偏好含义见 [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。
- 组件卸载时取消循环与监听、断开观察器、释放 geometry / material / texture / render target 等资源。Three.js 资源需要显式清理，见 [官方清理指南](https://threejs.org/manual/en/cleanup.html)。

官网配置中后备图的标称尺寸为 1905 × 907、文件大小 86,560 字节，说明轻量静态后备完全可以成为设计的一部分。博客应制作自己的后备素材；此处数值仅用于理解资源尺度，未独立校验该图片的传输字节数。
