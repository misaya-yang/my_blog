# SEO Distribution And Public Index Contract Design

Date: 2026-07-09
Status: Proposed
Parent package: [2026-07-09-product-optimization-final-spec-package.md](./2026-07-09-product-optimization-final-spec-package.md)

## Summary

The blog is a public research archive. Discovery quality depends not only on UI search, but also on canonical URLs, metadata, sitemap, RSS/static indexes, and strict public visibility boundaries. This spec defines the public distribution contract.

## Goals

- Keep public indexing aligned with public discovery and Agent source boundaries.
- Preserve canonical route semantics across article, search, taxonomy, archive, and track pages.
- Make SEO metadata useful without theatrical or overclaimed copy.
- Prevent hidden, draft, admin, or private content from reaching public distribution surfaces.
- Keep multilingual labels and article metadata coherent for readers and crawlers.

## Non-Goals

- No paid SEO tooling.
- No analytics vendor migration.
- No autogenerated article content for SEO.
- No change to route structure unless separately approved.

## Current Evidence

- Public routes live in `client/src/App.tsx`.
- Public post visibility is enforced in `server/routers.ts`.
- SEO/static output code exists in `server/seo.ts`, `server/client-render.ts`, and `server/static-index.ts`.
- Shared site metadata lives in `shared/site.ts`.
- Client SEO helper exists in `client/src/lib/seo.ts`.
- Discovery APIs live under `appRouter.discovery`.

## Public Distribution Surfaces

- Browser routes: `/`, `/algorithms`, `/applications`, `/archive`, `/search`, `/tags/:slug`, `/categories/:slug`, `/about`, `/post/:slug`.
- Server-render/static metadata.
- Sitemap and RSS or equivalent public index output.
- Search and taxonomy result APIs.
- Agent public source cards and citations.
- Social preview metadata.

## Contract

### Visibility

- Public distribution only includes posts with published/public visibility.
- Admin-visible draft/hidden posts may be returned only to verified admin sessions.
- Public search, archive, taxonomy, RSS, sitemap, static index, and Agent knowledge must share the same visibility model.
- Local development seed fallback may help validation but must not loosen production visibility.

### Canonical Metadata

- Every public article has stable canonical URL, title, excerpt/description, publish date, update date when available, category, tags, and reading context where useful.
- Taxonomy pages should describe the topic, not use generic placeholder text.
- Search pages should not be indexed as low-value query permutations unless explicitly intended.
- No metadata should claim capabilities not implemented by the product.

### Language

- Public metadata should follow the runtime language where the route has localized chrome.
- Article title/excerpt remains authored content unless explicit translations exist.
- Generated labels in Markdown or article chrome must be covered by the public i18n contract.

### Agent Alignment

- Agent source URLs must be canonical public article URLs.
- Source cards should not expose admin-only route paths, raw IDs, private pasted context, or hidden article titles.
- Knowledge reindex and public distribution freshness should be checked together before release.

## Acceptance Checklist

- Public index tests verify hidden/draft/admin content is excluded.
- Article metadata tests cover canonical URL, title, description, publish date, and visibility.
- Sitemap/RSS/static-index tests share the route contract.
- Search and Agent source boundaries match public distribution boundaries.
- Social metadata is useful but restrained and factual.
